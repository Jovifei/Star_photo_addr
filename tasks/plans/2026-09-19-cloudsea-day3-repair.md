# 云海后日数据恢复计划

## 目标

修复云海页面后日（第 3 天）在上游压力层请求偶发失败后被长期显示为“数据不足”的问题；今日、明日、后日和三日总览都必须显示明确日期，并在数据可用时显示完整的云海条件字段。

## 行动项

- [x] 用真实接口和受控夹具分别复现今日、明日、后日、三日总览的请求/缓存行为。
- [x] 为后日降级缓存、重试、日期标签、surface 与 pressure 字段完整性补充失败测试。
- [x] 修复请求并发/降级缓存边界，保持上游不可用时 fail-closed，不伪造云海评分。
- [x] 实现日期标签：今日、明日、后日均显示月/日与星期。
- [x] 运行云海专项单元/集成/E2E，再运行完整静态检查和浏览器回归。
- [x] 复现截图中的详情卡片收缩/裁切，覆盖 320–1280px 与横屏尺寸的逐卡片遮挡、溢出和相邻边界检查。
- [x] 修复云海详情所有主数据卡片的自适应高度、长文案换行和窄屏排列，确认站内不存在遮挡内容的浮动控件。
- [ ] 重新生成 exact-SHA standalone，部署后完成 ECS/public acceptance 后关闭。

## 验收标准

- `2026-09-21` 等后日请求在压力层可用时返回 54/54 个地点的可解释字段。
- 压力层失败时页面明确显示数据不足/来源状态，并且后续刷新不会被 30 分钟的“新鲜”降级缓存永久挡住。
- 四个日期选择项可读出对应日期；三日总览请求三天而不漏掉后日。
- 每个已声明数据字段都有 schema/缺失值/日期覆盖测试；不得用合成数据冒充上游结果。
- 每个详情卡片满足 `scrollHeight <= clientHeight`、`scrollWidth <= clientWidth`，相邻主卡片至少保留布局间距；320、375、390、430、577、768、844 横屏和 1280 宽度全部通过。
