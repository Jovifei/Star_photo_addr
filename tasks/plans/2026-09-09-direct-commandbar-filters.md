# v1.0.11 顶部直接筛选控件纠正

## 目标

把首屏必要的地点筛选参数直接放入顶部命令栏：

- 参考暗空档位 B1–B4：B1 极暗、B2 自然暗夜、B3 乡村夜空、B4 乡村/郊区过渡；
- 一个评分时间滑块；
- 一个推荐分数门槛滑块；
- 保留“仅显示达到推荐门槛的地点”开关。

顶部控件必须默认可见、无需打开新面板；完整统计、四档推荐颜色筛选等低频细节仍由既有地点设置面板承载。

## 实施顺序

1. 在工作区命令栏 E2E 中先断言无 `recommendation-settings`，并断言四个 Bortle 按钮及两个滑块直接可见，观察旧实现 RED。
2. 抽取轻量顶部控件，复用 `useStore` 的 Bortle、评分时次和推荐门槛状态；删除命令栏对完整 `ObservingMapControl` 的展开挂载。
3. 将 Bortle 筛选条迁移到命令栏，保留 B1–B4 的可见解释、键盘语义、计数和目录参考边界；移除地图重复挂载。
4. 更新响应式 CSS，使搜索框保持约 220px、桌面 1280/1440 命令栏单行呈现，窄屏按可读顺序堆叠且无水平溢出。
5. bump 到 v1.0.11，同步 package lock、应用内版本记录、两份 Changelog、工程记录、测试和 lessons。
6. 运行 focused RED/GREEN、`npm run check`、E2E、live/data-source/audit 门禁；审阅 diff 后提交、推送、合并和部署。

## 数据与状态边界

- B1–B4 仅筛选整理点位目录，不进入实时天气评分、SQM 或暗空栅格数值。
- 评分时间和推荐门槛继续使用现有 `cloudState.activeForecastTime`、`recommendationThreshold` 及对应 LocalStorage；不改算法和 API。

## 验收证据

- 命令栏默认可见四个 Bortle 档位、评分时间滑块、推荐门槛滑块；不存在展开式评分设置 DOM。
- 调整控件会更新地图筛选/评分并持久化，Bortle 文案明确说明四档含义。
- 桌面和移动端没有水平溢出；既有右侧/移动端详细面板回归不受影响。
