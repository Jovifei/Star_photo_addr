# 逐星统一视觉系统

> 状态：当前主规范。后续界面工作应以本文件、`src/app/theme-unified.css` 与
> `src/features/planner/planner-unified.css` 为准；仓库中早期自动生成的浅色、
> 靛蓝或“地产豪华风”设计稿只作为历史资料，不再作为实现依据。

## 1. 产品气质

逐星不是通用后台，也不是旅游营销页。它是一套在低照度环境下使用的**夜间观测决策台**：

- 地图优先，数据必须能快速支持“今晚去不去、去哪、几点去”的判断；
- 视觉保持克制、安静、低白光，避免大面积高亮和娱乐化霓虹；
- 强调天文摄影主题，但不牺牲天气、时次、数据来源和风险状态的可读性；
- `逐星`、`推荐观星地点`、`星野决策` 是同一产品的三个工作区，不应表现成三套网站。

## 2. 颜色语义

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 夜幕 0 | `#02070B` | 页面底色、地图外背景 |
| 夜幕 1 | `#041018` | 深层背景 |
| 夜幕 2 | `#071821` | 卡片、表头、输入区域 |
| 观测青 | `#79CFE2` | 当前选择、可用状态、主要交互 |
| 观测青亮 | `#B0E6EF` | 深色背景上的强调文字 |
| 月光琥珀 | `#D4B273` | 天文标题、时间窗口、谨慎提示 |
| 风险红 | `#CB7768` | 降水、阻断、错误、危险操作 |
| 主文字 | `#E7E7E0` | 标题与关键数据 |
| 次文字 | `#91A4AB` | 说明、来源、次要标签 |

语义约束：

- 青色表示“当前、可用、可操作”，不同时承担危险含义；
- 琥珀表示“月光、时间、需要留意”，不是失败；
- 红色只用于明确阻断、错误和降水风险；
- 紫色只允许在确有独立数据语义时使用，不作为通用面板主题；
- 禁止重新引入大面积靛蓝 `#1A2154 / #20295B` 旧仪表盘配色。

## 3. 字体与数据排版

- 正文：`Noto Sans SC Variable`，回退到系统中文无衬线字体；
- 品牌与少量主标题：宋体类衬线字体，建立天文观测气质；
- 坐标、时间、模型名、评分：等宽字体并使用 `font-variant-numeric: tabular-nums`；
- 标题不使用全大写英文堆叠；中文信息优先，英文只作为短标签和数据源名。

## 4. 组件规则

### 顶部导航

三个工作区固定为：`逐星 / 推荐观星地点 / 星野决策`。当前项采用青色半透明胶囊，
跳转时保留地点、模型、观测夜和时次。移动端允许横向滚动，不压缩成不可读缩写。
“数据依据与局限”属于安全与可信度入口，窄屏可收敛为 `36px` 信息图标，但不得隐藏。

### 面板与卡片

- 使用墨黑到青黑的轻微渐变；
- 统一 `14px` 大卡片圆角、`8px` 控件圆角；
- 边框透明度低于文字，避免每个区域都像表格；
- 阴影只用于层级，不使用大范围彩色光晕；
- hover 不缩放，不造成布局跳动。

### 控件

- 常规可点击高度不低于 `36px`，关键操作不低于 `40px`；
- 所有键盘可操作元素必须有可见焦点；
- `active`、`selected`、`aria-current` 与视觉状态一致；
- 禁止仅依赖颜色表达状态，需同时保留文字、图标或边框。

### 数据矩阵与图表

- 小时矩阵统一采用青黑表头，选中列使用观测青描边；
- 云量使用青色，温度/月光使用琥珀，降水和阻断使用红色；
- Tooltip、坐标轴、网格线应使用本规范的夜幕与文字色；
- 新增图表不得直接复制旧靛蓝 ECharts 配色，应优先从共享主题常量取色。

## 5. CSS 所有权

当前为渐进式收敛：

- `src/app/globals.css`：历史结构、地图定位与业务组件基础样式；
- `src/app/theme-unified.css`：全产品视觉语义和共享组件最终覆盖；
- `src/features/planner/planner.css`：迁移后的星野决策结构布局；
- `src/features/planner/planner-unified.css`：以 `.planner-root` 严格限定的统一视觉覆盖。

新增主题样式必须进入上述统一层，禁止再创建第四套颜色变量。后续重构可逐步把已验证的覆盖
合并回基础文件，但在合并前必须保持导入顺序：基础样式在前，统一视觉层在后。

## 6. 路由与状态一致性

- `/`：逐星地图，默认坚持“今晚优先”；
- `/sites`：兼容入口，重定向到 `/?view=light-pollution&panel=sites`；
- `/planner`：多地点、多夜晚决策工作区；
- `/viirs` 与 `/stargazing-finder-dark`：旧收藏兼容入口，重定向到统一光污染视图；
- 所有兼容重定向必须保留 `lat/lng/name/elevation/night/model/forecastTime/observationTime/overlay`；
- 主地图共享导航和数据说明弹窗通过 `buildProductHref()` 构造；Planner 现有 `productHref()` 必须维持同一参数协议，后续迁移时再合并实现；
- 主地图可主动丢弃历史夜晚和过期小时，但不得丢失地点、模型或用户明确选择的工作区；
- URL 状态桥接的幂等键必须包含路径；相同查询参数在不同工作区可能具有不同语义。

## 7. 交付检查

每次界面改动至少检查：

1. `375px / 768px / 1024px / 1440px` 四档宽度；
2. 三个工作区导航状态和跨页参数；
3. 键盘焦点、Esc 关闭、对话框焦点回归；
4. 小时矩阵、卡片、按钮、状态色是否仍遵守统一语义；
5. `npm run check`；
6. Chromium E2E，尤其是兼容路由、数据说明弹窗、移动端来源入口和推荐面板。
