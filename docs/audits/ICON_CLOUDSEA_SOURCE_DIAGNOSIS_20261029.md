分析对象是已保留的 2026-10-27 六份生产供应商捕获：三批 `ncep_gfs025` 压力响应及三批 `ncep_gfs013` 地面响应，各批 18 个地点。请求为 `Asia/Shanghai`、`unixtime`、`cell_selection=nearest`、`elevation=nan`；三份压力响应 SHA256 均匹配其原始请求记录。

54 个地点的 GFS025 地面六字段均未同时提供可用数值；GFS013 对应六字段覆盖 54/54。两者是分开的网格，地面网格海拔不能代替 GFS025 原生压力网格地形。GFS025 压力字段单位无错；其可选 2m 温度 54/54 全 null 且单位 `undefined`，现有代码已将其作为可选字段处理。

这 19 个被整日拒绝的地点，在 133 个晨晚目标小时中，71 个小时本身没有这些异常，另外 62 个小时至少有一层异常。若仅统计其余数值合法且高于模式地形的完整压力层，133/133 小时都仍有至少六层；这**只是数据完整性统计**，不是 133 小时可评分、无误报或预测命中率提高的证明。

整份拒绝发生在 `src/lib/pressure.ts:318` 到 `:321`；范围校验在 `src/lib/providerWeatherIntegrity.ts:4`。现有 `src/lib/pressureIntegrity.ts:15` 允许缺云量的热力层进入垂直分析，而 `src/lib/cloudsea.ts:325` 对空云量使用零参与云/晴判断：若把异常云量直接变成 null，低湿度时可能被误当作晴层。简单删层还可能跨越未知层连接云 deck，或错误判定山顶附近有晴空边界。GFS 压力层云量和位势高度的定义见[官方 GFS 文档](https://open-meteo.com/en/docs/gfs-api)。

## 待复核方案与验证

1. 对 ICON，保留无能见度时的不可评分状态；可在产品中明确展示该模型能力限制，并由用户显式选择完整 GFS 或 Best Match 模型。是否改变默认模型或验收语义属于待复核决策，不能仅为让门禁变绿而改变探针。
2. 对压力层，可研究把异常隔离到对应地点、时次和整层，同时显式保留未知层及原因，阻止它成为晴层、云顶上界或可跨越的连续 deck。只有单位、时间轴、网格身份和足够有效层仍合格时才评估其余信息；任何越界值都不截断或冒充真实值。
3. 回归应覆盖 101 云量与湿度、异常时次邻近有效时次、异常层位于山顶及云顶边界、缺云量不能构造晴空、跨未知层不能构造完整 deck、错误单位/时间轴仍拒绝、完整合法数据结果不变。对历史捕获和新的独立视觉样本分别验证覆盖、漏报及高分误报；不得在已使用的留出集上调参后宣称独立改善。

上述方案尚未修改或测试产品代码，需先由上一级复核后再决定实施与发布。
