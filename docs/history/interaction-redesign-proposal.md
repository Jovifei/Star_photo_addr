## 一、现状审计：为什么"用起来怪怪的"

### 1. 三种"切换"混在三个不同位置，没有层级

现在界面上同时存在三种性质的切换，但散落在各处：

| 切换性质 | 含义 | 目前位置 |
|---|---|---|
| **产品/空间切换** | 今夜观测 / 暗夜选址 / 观星计划 | 顶栏 NavTabs |
| **预测主题切换** | 星空 / 云海（未来 +火烧云） | 观星计划页面中部 control-strip |
| **图层/数据源切换** | 卫星云图 / 综合决策 / 光污染 | 右侧 CloudControl 面板内 tab |

用户想"换个玩法"时需要在不同角落找开关，心智模型建立不起来——这是"不舒服"的根源。

### 2. 图层切换有两个重复入口

- `ObservingMapControl`（左侧"观星地点"面板）里有 **卫星云图 / 光污染 / 综合决策** 三模式按钮（`MODES`）；
- `CloudControl`（右侧"云量与图层"面板）里有 **卫星云图 / 综合决策 / 光污染** 图层 tab。

两者操作同一个状态（`mapViewMode` + `overlayMode`），但命名顺序不一致（"综合决策"位置不同）。用户分不清哪个是权威入口。

### 3. 云量预报滑块承载 73 个时刻，无法定位

`CloudTimeline` 把当前至未来 72 小时（73 个整点）塞进一根 `<input range>`：

- 只有 4 个刻度标签（均匀取样），找不到"明晚 22:00"这种目标时刻；
- 白天和深夜混排，一屏滑过去不知道自己在哪天；
- 展开的逐小时矩阵（`HourlyForecastMatrix`）其实是好的浏览工具，但藏在"展开数据"按钮后面，默认收起，发现性差；
- 播放固定 1.5s/帧，无法调速；
- 卫星观测轴（24h）同样只有 5 个刻度。

### 4. 星空/云海开关位置突兀

观星计划把"预测天数 / 摄影模式（星空/云海）/ 附近推荐 / 数据新鲜度"挤在同一行 control-strip。星空 vs 云海本质是**预测主题**（同一份夜间预报、不同评分口径），不是页面参数；塞在天数开关旁边语义降级，且与地图产品没有任何位置呼应。将来加入火烧云后这里会变成三选一，更乱。

### 5. 浮动面板数量偏多

地图页常驻浮动块：搜索卡、观星地点面板、云量面板、暗夜图层面板、图例、视图快捷、面板布局管理器（顶中一整行）、底部时间轴、右下附近排行。面板可拖动+吸合已实现，但 9 个浮层的默认布局没有信息优先级，新用户第一眼不知道先看哪。

## 二、目标心智模型（三层切换）

```
第 1 层  产品（我在哪个空间）      → 顶栏，固定
第 2 层  主题（我要预测什么）      → 地图左上·标题区旁，全产品同位置同形态
第 3 层  图层（我用什么数据看）    → 地图顶部居中·图层条，唯一权威入口
```

其余一切（色阶、模型、通道、Bortle 阈值）都是第 3 层的"高级项"，收进右侧面板。

## 三、修改项清单（逐项可勾选）

### A. 时间轴重构 —— 解决"根本没法查看那么多数据"【P1】

`CloudTimeline` 改为**按夜分组的轨道式时间轴**：

```
┌──────────────────────────────────────────────────────────────┐
│ ▶ 播放  1×  │ 今晚 8/22 ▼                                     │
│ ●━━━━━┿━━━━━┿━━━━●─╌白天╌─●━━━━━┿━━━━●─╌╌─●━━━━              │
│ 20   22   0    2   5        20   23   2   5                    │
│        今晚(选中夜高亮)      │      明晚       │  后天 …        │
└──────────────────────────────────────────────────────────────┘
```

- 每晚一段（20:00–05:00），晚与晚之间的白天折叠为窄缝；
- 小时刻度**可直接点选**（不只是装饰 tick），点击直达该时刻；
- 夜标签（今晚/明晚/后天…）兼作快捷跳转，与现有 `changeNight` 一致；
- 键盘：`←/→` ±1 小时，`PgUp/PgDn` 跳一整夜，`Home/End` 到首/末；
- 播放速度 0.5× / 1× / 2× 可选；
- "展开数据"（逐小时矩阵）改为**选中点位后首次自动展开**，用户手动收起后记住偏好（localStorage）；
- 卫星观测轴（24h）同样刻度点选化。
- "今晚 / 5 夜 / 7 夜"范围切换保留，与轨道分组天然对应。

### B. 主题切换器统一 —— 星空/云海/（未来火烧云）【P1】

- 新建共享组件 `ForecastThemeSwitch`（图标分段控件：🌌 星空 / ⛰️ 云海）；
- **观星计划**：从 control-strip 移出，放到页面标题区（`section-kicker` 一行）右侧；
- **今夜观测**：地图左上、搜索卡下方放同一组件（当前地图隐含"星空"主题，云海主题切换评分口径与配色权重）；
- 两个产品**同位置、同形态**，后期加第三主题（如朝晚霞指数、银心可视化）直接挂进同一控件；
- control-strip 只留：预测天数、附近推荐、新鲜度。

### C. 图层切换收敛为唯一入口【P1】

- 把 `CloudControl` 里的"图层模式" tab **提升为地图顶部居中的全局图层条**（卫星云图 / 综合决策 / 光污染）；
- `ObservingMapControl` 里的三模式按钮**移除**（消除双入口），该面板回归纯"观星地点筛选"职责；
- `CloudControl` 面板内保留：数值云量通道、色阶、模型选择、数据源状态（高级项）；
- 命名统一为一套：卫星云图 / 云量预报 / 光污染（现在"综合决策"与 forecast-cloud 的映射容易误解，图层条直接叫"云量预报"，综合视图作为云量预报的默认呈现）。

### D. 火烧云预测地图入口【P3，需先定数据源】

两个候选方案：

- **方案 1（推荐）：独立地图页，入口在顶栏，与今夜观测并列**
  - 顶栏变为：今夜观测 / 暗夜选址 / **火烧云** / 观星计划；
  - 路由 `/fireglow`，复用 `MapStage` 地图基座 + 中国边界 + 搜索；
  - 时间轴域改为**晨昏窗口**（日出/日落 ±2~3 小时），评分口径 = 太阳高度角 × 中高云量 × 气溶胶（AOD），数据源需调研（Open-Meteo 有 cloudcover 中高层 + aerosol 需验证）；
  - 理由：火烧云与星空的**时间域不同**（晨昏 vs 夜间）、**数据通道不同**，塞进同一页会让底部时间轴状态机继续膨胀；暗夜选址已是"独立空间"的先例。
- **方案 2：作为今夜观测内的第三个主题**（挂进 B 的 ForecastThemeSwitch）
  - 优点：不加页面；缺点：时间轴要在"夜间域/晨昏域"间变形，主题与图层两个维度会打架，不推荐。

  无论哪种，入口位置与形态都与其他产品一致（顶栏 tab），满足"入口不想不一样"的诉求。

### E. 浮动面板默认布局与收纳【P2】

- 默认布局按信息优先级固定：左上搜索+主题 → 左中观星地点 → 顶部图层条 → 右上云量高级项 → 底部时间轴（常驻，不可拖）；
- `MapPanelManager`（面板布局管理器）从顶中常驻改为**齿轮弹出菜单**，不再占一行；
- 右下"附近排行"浮球保留，但与观星计划的"附近推荐"开关共用一份半径偏好。

### F. 点击链路统一【P2】

- 任何点位点击来源（地图 marker / 搜索 / 观星地点列表 / 附近排行 / 推荐标记）→ 统一行为：**选中 + URL 同步 + 右侧 SidePanel 打开**；
- "加入观星计划"只从 SidePanel 发起（现状已基本如此，补齐观星地点列表项的按钮即可）；
- 跨产品跳转统一走 `productHref`（已实现，保持）。
