# 手机数据密度与滚动重设计

状态：设计与复现进行中，尚未发布。现网仍为378161f。

## 用户要求

四入口同等地位；顶部直接选择日期与时段；缩小视觉字号；展示更多可信数据；地图和详情的滑动范围清楚。保留系统文字放大和缩放能力。

## 已确认原因

- ICON缺能见度时应暂缓评分；当前详情同时依赖评分对象展示月照、暗夜时长和银河高度，导致独立天文事实也被隐藏。
- 手机最终CSS将结论设为20px、摘要固定95px、数据/证据单列，降低信息密度。不能仅归因于设备缩放。
- 页面有多层手机CSS，必须检查最终计算样式与滚动所有权，不能再增加无边界覆盖。

## 方案选择

采用紧凑地图工作台，复用四入口共享壳：顶部搜索与日期；地图主体；可展开数据面板；四入口一致导航。单纯整体缩放不能解决数据空白和嵌套滚动；全屏表格会削弱地图选址，暂不采用。

## 可执行规格

- 日期和晨/晚选择按内容宽度排列，不铺满宽屏、不要求先点击调整；手机空间不足才自然换行。
- 地点/结论视觉字号14–16px，常规数据13–14px，辅助来源11–12px；触控区域独立于文字大小。输入框保留16px与浏览器缩放。
- 摘要采用内容高度，避免固定95px空白；气象核心值优先采用紧凑两列或键值行，不显示六张巨大的空值卡。
- 天文事实独立于天气评分，以地点和可信时间计算；评分缺字段继续暂缓，明确具体缺失项。不得混合ICON与Best Match字段形成伪完整模型。
- 面板只有一个纵向滚动容器；内部卡片不再自带纵向滚动。小时表可独立横向滚动，整页不得横向溢出；地图手势与面板滚动分离。
- 缓存数据保留来源时间、模型、stale标识；刷新失败不删除可用事实，不伪造评分。
