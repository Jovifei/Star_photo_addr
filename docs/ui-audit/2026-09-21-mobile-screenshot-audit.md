状态：待 Jovi 审核。此次只做问题盘点和标记，不修改页面代码，不提交，不部署。

## 1. 审计范围

本报告审计用户提供的 8 张 iPhone Safari 截图。截图原始尺寸均为 `1125 × 2436`，画面包含 Safari 状态栏/底部浏览器工具栏；因此涉及浏览器安全区的判断，先记录为“截图可见问题”，根因仍需在真实运行态确认。

审计目标：逐张检查页面布局、参数文本、日期语义、地图/画布、图例、错误状态、滚动区域和固定悬浮控件，确保主数据不被遮挡、用户能理解当前状态、核心操作在手机上可达。

审计标准：

- 项目 `ui-ux-pro-max`：移动优先、无页面级横向溢出、固定层预留安全间距、数据图例不能只依赖颜色、错误/空数据必须给出原因和恢复路径。
- Apple Human Interface Guidelines：布局应适应屏幕尺寸、方向、系统安全区和动态文字；控件应与内容对齐并保持清晰层级。
- Material Design：触控区域建议至少 `48 × 48dp`，相邻触控目标通常至少保留 `8dp` 间距。
- WCAG 2.2：固定内容、弹层和通知不能把当前焦点或核心内容完全遮住。

问题编号格式：`S1-A` 表示第 1 张截图的 A 项问题。坐标采用原图大致区域/百分比，方便在原图中定位；不是 DOM 坐标。

严重等级：

- `P0`：主数据不可用、操作不可达或内容被遮挡，影响基本使用。
- `P1`：主要信息理解困难、布局明显不合理或错误状态表达不完整。
- `P2`：可用但存在可读性、层级、对比度或视觉一致性问题。

审计证据分两类：

- `[截图可确认]`：仅凭画面即可确认的显示问题。
- `[需运行态确认]`：截图显示异常，但要通过 DOM/Computed Style/API/真实设备才能确定根因。

## 2. 总体结论

8 张截图全部存在需要处理的问题，主要集中在五类：

1. 移动底部详情面板仍保留桌面式“左侧露出地图条带 + 右侧固定按钮”的结构，导致内容区宽度不足、固定控件压住数据卡片。
2. 日期按钮在窄屏中把“周一/周二/周三”拆成独立行，三日总览范围也被拆开；信息虽然存在，但阅读速度和语义完整性较差。
3. 地图页面的错误/降级状态与画布本身没有形成清晰的一致状态：一张图显示 HTTP 502，一张图显示 HTTP 429，一张图只有黑色画布和少量城市标签。
4. 图例、点位标签和固定工具栏没有为移动画布预留空间，造成地图内容被图例遮住或点位/城市标签相互拥挤。
5. 顶部控制区在手机首屏占据过高比例，地图和真实观测结果被推到首屏下方；日期、评分时间和地图标题还出现跨午夜语义不一致。

建议优先级：先处理 `S2 / S3 / S4 / S5 / S8` 的面板宽度和遮挡，再处理 `S1 / S6` 的数据错误状态与日期语义，最后处理 `S7` 的地图点位和图例密度。

| 首屏控制密度过高 | S1、S6、S7 | 筛选、日期、模式、Beta 说明连续占据首屏 | 保留当前筛选摘要和主操作，低频说明/高级筛选渐进披露。 |

## 5. 暂不下结论的事项

以下事项从截图看起来有风险，但在进入修复前必须通过运行态证据确认，避免仅凭截图误改业务：

- S1 “9月20日”与“9月21日”是否是跨午夜观测夜的正确业务语义。
- S1 HTTP 502、S6 HTTP 429 是截图瞬时上游故障、缓存降级还是前端状态机没有恢复。
- S2/S6 黑色地图是底图请求失败、地图容器未挂载、还是截图时刻尚未加载完成。
- Safari 底部工具栏导致的视觉裁切是否为页面缺少 safe-area/viewport padding，还是截图滚动位置造成的暂时现象。
- “详情/收起”按钮是否真的遮挡 DOM 内容，需要通过浏览器几何检查 `getBoundingClientRect` 和相邻元素边界确认。

## 6. 后续修复前的验收门槛

本报告不授权直接修改。Jovi 审核后，如果确认进入修复，建议把验收拆成以下可测量门槛：

1. 在 `320 / 360 / 375 / 390 / 414 / 768px` 宽度和手机横屏下，页面级 `scrollWidth <= innerWidth`。
2. 移动详情面板全宽或明确的安全边距，不能出现只露一条面板边缘的状态。
3. 固定按钮与任何正文卡片的矩形区域不相交；滚动到最后一项时仍有足够底部 padding。
4. 日期按钮不在中文日期语义中间断行；今日/明日/后日、月日、星期和三日范围分别可读。
5. 错误、空数据、旧快照、部分数据和正常数据具有不同的可视状态，并且错误状态有重试/等待/来源说明。
6. 地图图例不遮挡主要点位；点位标签有碰撞规避或仅对选中点显示，颜色不是唯一信息通道。
7. 主要触控目标达到至少 `44px`（Web 移动端）或 `48dp`（Material 参考），相邻目标保留足够间距。
8. 真实 iPhone/Android 设备分别验证安全区、浏览器底栏、系统字体放大和横屏，不能只用 Playwright 模拟视口替代。
