## 目标

修复用户现场发现的评分颜色、Bortle 筛选、天气/云图降级反馈、火烧云宽屏布局和观星计划附近推荐问题；保留 PR #14 的移动端单抽屉行为；完成本地门禁、提交到 `main`、部署并验证公网 HTTP 入口。

## 已确认事实

- PR #14 的 `origin/fix/mobile-map-panel-dock-20260825` 与 `main` 树相同，是 squash 后的历史分支，不再重复 merge。
- 当评分快照不可用时，`ObservingSitesLayer` 将点位 band 设为 `unknown`，颜色为灰色；这是防止复用旧时次评分的安全行为，但当前提示不足。
- B1/B2/B3/B4 是 `ObservingMapControl` 中的静态统计元素，实际筛选只有 B1–B3/B1–B4 下拉框。
- 当前 `/api/data-status` 的天气源可能返回 HTTP 429；NASA GIBS 目录可用。天气源问题不能用假数据掩盖。
- 本地 Bortle/SQM 栅格是需要授权数据文件的可选能力，不是 npm/Docker 依赖；未安装时不能生成数值。
- 火烧云工作区使用 `1680px` 宽度上限和居中留白；需要改为地图占满剩余可视宽度。
- 取样点 `42.97,97.43` 在 100/200/300km 内没有全国观测库点；当前实现返回空推荐且没有解释。杭州附近测试点在相同半径下可得到 4/11/20 个点，说明距离计算本身可用。

## 设计决策

### 评分与 Bortle

- 评分快照加载中或失败时，保留空间点位但显示明确的“未评分/数据不可用”状态；评分门槛统计和 band 数量显示 `—`，不把未知当 0。
- 快照可用时继续使用四档颜色：85–100、70–84、55–69、0–54；颜色必须来自当前完整 ISO 时次和当前模型。
- 将 B1、B2、B3、B4 统计卡改为可点击的 Bortle 档位筛选；默认保持 B1–B3 选中。筛选状态与当前点位数量、地图点和推荐列表共用同一状态。
- 页面文案明确区分：`今夜观测` 按当前时次天气评分，`暗夜选址` 按长期暗空本底，`观星计划` 按候选池预测排名。

### 数据降级

- 云图目录失败时继续保留最近一次有效卫星帧，错误提示区分超时、上游 HTTP 状态和刷新冷却。
- Open-Meteo HTTP 429 只显示为天气降级，不伪造实时天气；服务器 API key 不在本次代码中生成或提交，待用户提供后作为部署环境变量配置。
- 本地 Bortle/SQM 和天地图 token 继续作为可选配置，状态文案增加“影响什么/不影响什么”。

### 火烧云与附近推荐

- 火烧云工作区取消固定 `1680px` 居中上限；排行栏保持可读宽度，地图填满剩余空间。
- 附近推荐先严格取半径内点位；如果结果少于 3 个，补充距离最近的点位，最多展示 8 个，并在每个补充点显示距离和“半径外补充”标签。
- 关闭附近推荐立即恢复原候选池；半径切换必须改变推荐集合或显示“该半径内无库点”的明确空状态。
