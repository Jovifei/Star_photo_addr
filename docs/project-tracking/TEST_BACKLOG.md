## 2. DEV-IOS-001：iPhone Safari 真机

| 字段 | 内容 |
| --- | --- |
| 状态 | `MANUAL` |
| 风险 | Safari 地址栏、安全区、定位权限、触控滚动、Canvas/瓦片和后台恢复与 WebKit 自动化不同 |
| 前置条件 | 正式或预发布 HTTPS；至少一台带刘海/灵动岛与 Home Indicator 的 iPhone；记录 iOS/Safari 版本 |
| 建议覆盖 | 当前受支持 iOS 主版本 + 前一主版本；窄屏和较大屏各一台更佳 |

### 步骤

1. 无痕模式打开首页，拒绝定位；确认搜索、地图点击仍可用；
2. 清除站点权限后重新允许定位；确认只选中一个合理地点；
3. 展开/收起云量、当前视野推荐、地点详情和数据依据 Dialog；
4. 竖屏完成“选择地点 → 切换模型 → 刷新 → 加候选 → 进入观星计划”；
5. 横屏重复核心操作，检查安全区、顶部导航和底部 Home Indicator；
6. 滚动时让 Safari 地址栏展开/收起，检查 `100vh/100dvh` 跳变；
7. 锁屏或切到后台 60 秒后恢复；确认状态不丢、旧请求不覆盖；
8. 使用弱网或关闭网络，再恢复网络；确认 stale/错误状态清楚；
9. 检查地图拖动、双指缩放、点击标记和面板滚动是否冲突。

### 通过标准

- 所有核心按钮均可点击，不被安全区或固定层遮挡；
- 页面无整屏横向滚动；
- 地址栏变化不会使核心操作永久移出视口；
- 拒绝定位后仍有完整替代流程；
- 后台恢复后地点、模型、图层和候选不被旧请求覆盖；
- Canvas、卫星瓦片和光污染图层失败时有可理解退化；
- 无未处理异常和白屏。

## 6. DEP-ECS-001：阿里云大陆 ECS 海外出口

| 字段 | 内容 |
| --- | --- |
| 状态 | `BLOCKED` |
| 风险 | GitHub Actions/本地通过，但大陆 ECS 到 Open-Meteo、NASA、NOAA 的 DNS、TLS、TTFB 不稳定 |
| 前置条件 | 确定 ECS 地域、系统、网络计费和安全组；具备 SSH；部署候选镜像 |

### 执行脚本建议

在 ECS 中对每个上游执行多轮：

```bash
for i in $(seq 1 20); do
  curl -sS -o /dev/null \
    -w '%{time_namelookup} %{time_connect} %{time_appconnect} %{time_starttransfer} %{time_total} %{http_code}\n' \
    'https://api.open-meteo.com/v1/forecast?latitude=30.2741&longitude=120.1551&hourly=cloud_cover&forecast_days=1'
done
```

同时执行：

```bash
dig api.open-meteo.com
dig gibs.earthdata.nasa.gov
dig services.swpc.noaa.gov
openssl s_client -connect api.open-meteo.com:443 -servername api.open-meteo.com </dev/null
curl -fsS http://127.0.0.1:3100/healthz
npm run check:data-sources -- http://127.0.0.1:3100
```

### 通过标准

- DNS、TCP、TLS 成功率 100%（测试窗口内）；
- 不出现持续性证书或 SNI 错误；
- 天气 p95 TTFB 建议小于 8 秒；GIBS 目录建议小于 12 秒；若不满足，必须评估代理/缓存；
- 应用超时与真实网络基线匹配；
- 第三方失败不导致 `/healthz` 失败或容器重启循环；
- stale 回退可用，错误不泄漏内部 URL/正文。

阈值是初始工程目标，首次测试后可依据实测更新，但任何调整必须记录原因，不能只为“让测试通过”。

### 证据

保存 ECS 地域、时间段、20 次原始测量、p50/p95、失败样本、容器日志和数据源状态 JSON。

- 主机名与证书匹配，证书链完整；
- 距过期至少 30 天或已验证自动续期；
- 页面无混合内容；
- 分享链接全部使用正式 HTTPS 域名；
- `/healthz` 与第三方健康解耦。

## 8. PERF-K6-050 / PERF-K6-100：压力测试

| 字段 | 内容 |
| --- | --- |
| 状态 | `DEFERRED` |
| 风险 | 多用户同时打开地图、请求天气或刷新，导致 Node 内存、Nginx 限流或上游配额异常 |
| 前置条件 | 隔离预发布环境；CPU/内存监控；禁止对第三方上游进行无节制 `refresh=1` 压测 |

### 场景比例

```text
60% 打开首页并读取缓存数据
20% 调用 forecast 正常查询
10% 读取 observing snapshot / 区域推荐
5% 打开 planner
5% 受控人工刷新（必须命中应用冷却，不能直接压第三方）
```

### 阶段

1. 5 VU 冒烟 2 分钟；
2. 逐步升到 50 VU，保持 10 分钟；
3. 50 VU 通过后，突发到 100 VU，保持 5 分钟；
4. 冷却 5 分钟，观察资源恢复。

### 初始通过标准

- 应用层请求错误率 `< 1%`，预期的 429 单独统计；
- 缓存命中接口 p95 `< 500 ms`；
- 无 OOM、容器重启、持续 5xx；
- 同 key 并发请求被合并；
- 强刷被冷却，不将 50/100 用户直接放大到第三方；
- 测试结束后 CPU/内存回落。

### 证据

提交 `tests/performance/` 脚本、k6 JSON/HTML、服务端资源曲线、Nginx/应用日志和结论。

## 12. SCI-SQM-001：Bortle/SQM 科学真值

| 字段 | 内容 |
| --- | --- |
| 状态 | `BLOCKED` |
| 风险 | 把 VIIRS 视觉夜光、模型估计或未授权栅格误写成现场 Bortle/SQM 实测 |
| 前置条件 | 来源和许可可核验的栅格；经过校准的 SQM 仪器；现场采样计划；足够地点和夜晚 |

### 最低采样设计

1. 选择城市、郊区、山区和暗夜地至少 10 个点；
2. 每点记录坐标、海拔、时间、月相/月高、云、湿度和透明度；
3. 每个地点连续读取多次 SQM，记录均值和离散度；
4. 避开明显车灯、建筑照明和云反射污染，或明确标记；
5. 同时提取栅格/模型值；
6. 分析偏差、区域系统误差和 Bortle 分类一致性。

### 初始验收建议

以下阈值必须在执行前由项目负责人确认：

- SQM MAE 建议 `≤ 0.5 mag/arcsec²`；
- Bortle 分类在 `±1` 级内的样本比例建议 `≥ 80%`；
- 若不达标，只能展示“视觉夜光参考”或置信区间，不得输出精确真值。

### 证据

- 数据许可与署名；
- 仪器型号、校准日期；
- 原始 CSV/JSON；
- 现场记录和照片；
- 分析 Notebook/脚本；
