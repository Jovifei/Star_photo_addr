# 工程修改跟踪：移动端地图面板侧边栏

> 日期：2026-08-25  
> 基线：`main@a31aa4d9cb45051c196c30de72b22573151ee7a9`  
> 分支：`fix/mobile-map-panel-dock-20260825`

## 1. 问题

手机端已有两轮“面板折叠与错位清理”修复，但仍依赖多个绝对定位面板在地图上纵向堆叠。不同手机高度、浏览器地址栏、安全区、横屏和旧 CSS 规则组合后，仍可能出现：

- 地点、云量、图层、图例和区域推荐互相遮挡；
- 为避免遮挡而隐藏的主题、视图和暗夜控件在手机上无法使用；
- 横屏手机宽度超过 768 px 后重新进入桌面浮窗布局；
- 面板占据大部分地图，用户难以拖动和观察云图。

## 2. 本次方案

新增统一的 `ResponsiveMapControls`：

- 桌面端继续使用原有浮动、拖动、缩放布局；
- 竖屏手机和短屏横屏手机使用右侧工具栏；
- 点击“图层 / 地点 / 云量 / 推荐”后，只打开一个侧边抽屉；
- 抽屉外点击、关闭按钮或 Escape 均可关闭；
- 打开后焦点进入抽屉，并在抽屉内循环；关闭后焦点返回触发按钮；
- 使用安全区内边距、44 px 以上触控目标和独立滚动区；
- 图层、主题、地图视图、暗夜条、图例和边界状态不再在手机上被永久隐藏，而是收纳进“图层”页；
- 地点筛选、云量控制和当前视野推荐各自独立成页，不再互相覆盖。

移动判定同时覆盖：

```text
max-width: 768px
或
max-height: 520px 且 max-width: 1024px
```

因此 812×375、844×390 等手机横屏尺寸不会退回桌面浮窗。

## 3. 代码结构

- `src/components/ResponsiveMapControls.tsx`：桌面/移动布局路由和无障碍抽屉；
- `src/components/MapStage.tsx`：只保留地图、标题、搜索和统一控制入口；
- `src/components/ObservingMapControl.tsx`：增加 `docked` 模式，在抽屉内保持完整展开；
- `src/app/mobile-map-controls.css`：侧边栏、横屏、安全区和旧绝对定位覆盖；
- `src/app/layout.tsx`：最后加载移动端覆盖样式；
- `tests/e2e/mobile-panel-dock.spec.ts`：竖屏、横屏、互斥面板、焦点、溢出和桌面回归。

## 4. 不变内容

本轮不修改：

- 云量、卫星、光污染和观星评分算法；
- 上游接口、缓存键、刷新冷却和阿里云部署配置；
- 桌面端拖动面板的本地存储格式；
- 地点和观星计划数据。

## 5. 验收门禁

必须通过：

```text
npm run check
npm run test:e2e
npm run test:e2e:cross-browser
```

重点断言：

- 375×812 竖屏只有侧边工具入口，不存在多块浮窗叠放；
- 812×375 横屏仍使用侧边栏；
- 一次只显示地点、云量、图层或推荐中的一个；
- 抽屉内容不越过视口，不产生页面横向滚动；
- Escape 关闭并恢复焦点；
- 1440×1000 桌面继续显示原有可拖动面板。
