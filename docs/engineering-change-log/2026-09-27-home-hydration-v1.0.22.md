# 2026-09-27 v1.0.22 首页跨时次水合热修

## 用户可见问题

v1.0.21 发布后，390×844 真实公网浏览器中的首页与暗夜选址兼容入口记录 React #418 水合错误。地图、底部面板可见，但不能把“能显示”当作无运行时错误。火烧云与云海的地图主体由纯客户端动态组件加载，未出现同一报错。

## 原因

1. 首页静态预渲染写入构建时的当前夜晚和小时；`StoreProvider` 原先在服务端和浏览器分别于模块加载时计算时钟。构建后跨小时或跨日访问，首次 HTML 与客户端状态不同。
2. `useMobilePanelViewport` 原先用 `useState(matchMedia)` 初始化：服务端默认桌面，手机浏览器首次渲染立即判为移动端。开发模式的 React 差异明确指出服务端多渲染了 `.workspace-width-controls`，客户端已换成候选列表。旧“当前小时”测试仅监听 console 且构建后立即执行，漏检此差异。

## 修复

- 根布局向 `StoreProvider` 序列化同一个初始 ISO 时间；首次水合共用这份快照，挂载后只在用户尚未选用其他日期/时次时同步实际时钟。
- 地图面板视口使用 `useSyncExternalStore`：服务端快照与水合首次渲染一致，随后订阅浏览器媒体查询，保留旋转和窗口变化响应。
- 回归在浏览器端把日期推进两天，分别验证桌面与手机的日期、导航交互和无水合错误。本机资源紧张时可用 `STAR_BUILD_CPUS=1` 限制 Next 页面数据 worker；默认构建配置不变。
