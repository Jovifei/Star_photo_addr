# STAR-20261126-01 云海移动页排版与面板交互

## 现象与修复

移动端点选山峰后，共用的面板逻辑会自动切到半展开。长数据提示也出现在收起态，使摘要高度随警告长度变化。底部四栏是全站导航，依次为今夜观测、暗夜选址、火烧云和云海。详细内容末尾的「查看版本更新记录」用于打开变更说明。

- 云海首次入页及分享链接恢复时显示摘要。搜索、地图和排行点选更新内容，面板高度由用户控制。
- 展开可分两步阅读，点击「收起」直接回摘要，键盘焦点返回「展开」。地图及面板拖动保留原有操作区。共用组件的其他入口保留逐级收起和原有点选行为。
- 山峰名称 16px、核心结论 17px、辅助信息 12px、状态说明 13px。沿用项目中文无衬线字体栈，加重标题和结论，数值使用等宽数字。底部导航保留当前栏目语义。
- 摘要区分数据覆盖不完整、读取异常和旧数据。展开保留详细原因、地面及压力层覆盖计数和数据来源。按日期合并重复原因并去掉搜索选点的重复分支。

## 技术链与审核

云海入口加载 CloudSeaApp。搜索、地图、分享状态与排行榜已经在该入口汇合，MobileDataSheet 负责独立的高度和焦点。云海排版由路由内 CSS 限定在移动视口。ProductHeader 中的 NavTabs 继续负责全站导航。

独立审核发现，通用摘要会弱化缺失和过期提示。最终摘要提供区分状态并保留状态播报，完整原因仍在展开态可读。天气接口、评分算法和调度流程沿用现行实现。

## 验证

- 同一离线天气和瓦片数据下，基线在 320px、390px 均复现选点后从 peek 跳到 half。修复版在两种宽度验证分享链接初态、长警告、一步收起、时段切换、触控高度和焦点返回。
- Turbopack 生产构建和应用源码定向 ESLint 退出 0。Chromium 的云海和共享地图入口回归 42 项通过，26 项因项目和设备条件跳过。最终断言分别在 Chromium 定向复跑 4 项和移动 WebKit 复跑 2 项通过。
- 离线浏览器回执和 390px 截图对应本地候选。截图使用模拟天气与占位瓦片，供检查字体和布局。
- 2026-11-26 22:24–22:25（台北时间），OnePlus 7 Pro（GM1910，Android 11）实体手机上的 Chrome 158，原生 CSS 视口 384×723。用 USB 回环加载候选，Chrome 调试协议向真机投递触摸输入。分享入页和搜索选点均保持摘要，字体 16/17px、摘要高约 88px、按钮触控区 48px、页面横向溢出 0。两步展开、从完全展开一步收起、焦点返回、时段切换、拖动地图和切换底部栏目均通过。
- 真机使用原 Chromium 验收同一份离线临安太子尖 GFS 样例，窗口平均 88/100，压力层 20/54，SHA-256 为 `35cb2033e9a2a616bd5ea012710c206948bff6b61a622204e41547fb926c0888`。样例服务 4 次，地图瓦片 45 次均由测试提供。Android Chrome 软键盘升起时，自动触摸按可视视口偏移换算坐标。该结果是物理设备上的离线交互验收。
