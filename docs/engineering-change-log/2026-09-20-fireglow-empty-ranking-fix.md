# 火烧云空排行二次修复记录

## 根因

上游限流或异常响应会产生全站 `score=null` 的快照。第一层 API 修复阻止了空快照缓存，但前端错误态仍无条件渲染“暂无达到 ≥0 分的地点”，因此视觉上仍像是正常的 0 分排行。

## 修复

- API 按有效评分点数 fail-closed：空快照不缓存、不覆盖有效快照；没有回退时返回 502。
- FireGlow 页面拒绝 HTTP 200 空评分响应。
- 错误态显示“暂无有效火烧云数据，请刷新重试”；只有真实快照成功但阈值过滤为空时，才显示“暂无达到 ≥N 分”。
- 502 错误保留上游具体原因（例如 Open-Meteo 429），避免把外部配额故障隐藏成普通空排行。
- 今日/明日/后日及七日日期统一显示月日和星期。

## 验证

- 60 个测试文件、350 项 Vitest：PASS。
- ESLint、TypeScript、Next 生产构建：PASS。
- 空快照 API 回归：2/2 PASS。
- FireGlow 空快照浏览器回归：1/1 PASS。
- 响应式专题回归：桌面平板、移动详情和横屏用例 PASS。
- ECS 部署后验证：app/worker healthy，FireGlow ICON/GFS 均因 Open-Meteo 匿名配额返回 502；这是外部数据源 BLOCKED，不将其误报为数据 PASS。
