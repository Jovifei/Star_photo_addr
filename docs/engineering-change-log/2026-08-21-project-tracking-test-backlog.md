## 1. 背景

剩余测试此前以一张简表记录，能说明“为什么没做”，但不足以让后续 Codex 或人工直接执行，主要缺少：

- 全局唯一任务 ID；
- 前置依赖与目标环境；
- 具体步骤；
- 可量化通过标准；
- 证据目录与输出格式；
- 工作包优先级和执行顺序；
- 每次提交解决什么的统一台账；
- 合并后必须同步哪些状态文档。

## 2. 方案选择

采用仓库内 Markdown，而不是单独 Excel：

- 与代码一起版本化；
- 可链接提交、PR、测试结果；
- 可由 Codex 直接维护；
- Git diff 能追踪状态变化；
- Excel 只作为汇报导出，不作为事实源。
