## 结论

参考站的核心不是一张“天气表”，而是一个地图优先的观测决策流程：先在地图理解暗空环境，再选地点和日期，最后查看逐小时天气、月光、海拔和数据边界。当前仓库已经具备更深入的点位评分、硬门禁、云海潜力、逐小时图表和气压层云高，因此应把地图作为新增入口，而不是重写现有页面。

## 关键 UX 发现

1. 地图是主任务入口。用户可以先看地理环境，再进入天气决策，比纯表格更适合发现陌生机位。
2. “光污染”和“天气”必须分层表达。参考站会明确数据年份、分辨率和模型边界；本项目不能把普通深色底图冒充暗空图。
3. 时间轴应与地图选点保持同屏。选中地点后立即反馈未来多夜的可拍性，比先保存再刷新更顺畅。
4. 远期预测必须降级为趋势。当前仓库已有 8 天后“趋势”标签，应继续保留。
5. 山地安全不能由单一分数替代。参考站和当前仓库都需要道路、现场云况与临近出发复核提示。

## 本轮实现取舍

- 保留现有星空靛蓝视觉系统、导航和评分逻辑。
- 新增“地图”导航，不重写今晚、对比、点位、详情抽屉。
- 地图使用 Leaflet + CARTO 深色底图；地图本身只承担空间选择。
- 地名搜索使用 Open-Meteo Geocoding API；地图点击点位的海拔使用天气模型地形，界面明确标注。
- 光污染、多模型云图、行政边界与暗夜候选点需要可靠数据工程，进入 Phase 2。
